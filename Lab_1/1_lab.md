# Отчёт по лабораторной работе №1. Концепция и спецификация проекта

**Тема:** Разработка корпоративной платформы сбора и анализа обратной связи сотрудников (на примере ООО «Директум»)

## 1. Формирование команды
Команда состоит из двух человек. 

## 2. Выбор идеи проекта
**Тема:** Сайт для внутренних опросов ООО «Директум».
**Цель:** Получить собственный внутренний инструмент для проведения внутрифирменных опросов, обеспечивающий безопасность персональных данных и автоматизацию HR-процессов.

## 3. Описание проблемы и целевой аудитории

### 3.1. Проблема
В ООО «Директум» регулярно проводятся внутренние опросы для сбора обратной связи от сотрудников (аттестация, завершение наставничества/обучения, увольнение, периодические опросы мотивации). 

В соответствии с требованиями по обеспечению безопасности персональных данных (152-ФЗ), компания не может использовать внешние сервисы (Яндекс.Формы, Google Forms), так как в них отсутствует полный контроль над конфиденциальностью доступа к персональной информации сотрудников.

Отсутствует единый внутренний инструмент, позволяющий: проводить опросы методом 360, рассылать опросы по событиям (аттестация, перевод, завершение испытательного срока, наставничество), хранить результаты с разграничением доступа (руководитель/HR), автоматически удалять просроченные опросы и удалять результаты после их экспорта в электронный документ.

### 3.2. Целевая аудитория
- **Сотрудники** – проходят опросы по направленным им ссылкам, оставляют обратную связь.
- **Руководители подразделений** – инициируют отдельные опросы, запрашивают доступ к результатам по своим сотрудникам, формируют обратную связь по подчинённым.
- **HR-служба** – администрирует опросы и шаблоны, загружает и поддерживает иерархию подразделений и сотрудников, выдает/контролирует доступ к результатам, управляет автоматизацией по событиям, осуществляет экспорт результатов.
- **Технический администратор** – отвечает за развёртывание решения (Linux + nginx + Docker), интеграцию с корпоративным источником (Excel на текущем этапе), настройку почтовой рассылки.

## 4. Аналитический обзор аналогов

В рамках обзора рассматривались два класса решений: self-hosted (программы с открытым исходным кодом, разворачиваемые на собственном оборудовании) и on-premise (коммерческие продукты, устанавливаемые на серверах внутри компании).

### 4.1. Список аналогов
1. **LimeSurvey** – конструктор опросов с ролями, шаблонами, экспортом.
2. **Formbricks** – фокус на опросах внутри продукта и HR-опросах, управление доступом, веб-интерфейс.
3. **Typebot** – визуальный конструктор, email-интеграции возможны через настройки.
4. **SurveyJS** – мощный визуальный редактор вопросов, можно внедрить в собственное веб-приложение.
5. **Nextcloud Forms** – не требует усилий в развёртывании, разграничение доступа по пользователям.
6. **OpnForm** – минималистичный конструктор форм/опросов с шаблонами.
7. **Jotform Enterprise / Jotform On-Prem** – богатый функционал, но требует лицензии, сложнее в учебном контексте.

### 4.3. Вывод о месте собственного продукта
Анализ показал: ни одно из рассмотренных готовых решений **полностью** не покрывает совокупность требований ООО «Директум» в «коробочном» виде. Ключевые пробелы аналогов:
- **Метод 360** – нет готового модуля в связке с орг.иерархией.
- **Автоматизация по HR-событиям** – требуемый набор правил отсутствует.
- **Специфичный жизненный цикл** – удаление результата сразу после экспорта и автоудаление опроса.
- **Точное разграничение по иерархии** – доступ руководителя только к своим подчинённым.

**Заключение:** целесообразно разработать собственный внутренний сайт. В качестве референса для визуального конструктора используется подход SurveyJS Creator, архитектура выстраивается с нуля под стек ТЗ.

| **NFR-02** | **Производительность.** Время отклика API при 50 параллельных запросах ≤ 300 мс. | 1) p95 ≤ 300 мс (k6). 2) Экспорт не блокирует UI > 2 сек. 3) Импорт 1000 сотрудников ≤ 10 сек. 4) Список опросов ≤ 1 сек. | Must |
| **NFR-03** | **Надёжность.** Корректная обработка планировщика без потери событий. | 1) Логирование ошибок. 2) Идемпотентность рассылки при перезапуске. 3) Health-check. 4) Фиксация ошибок SMTP. | Must |
| **NFR-04** | **Совместимость стека.** ASP.NET Core 8, React, Linux+nginx+Docker. | 1) Сборка под .NET 8. 2) Production-сборка React. 3) Docker в Linux. 4) Конфиг nginx. 5) `docker compose up`. | Must |

## 9. Отчёт о работе с агентом


### 9.1. Примеры промптов и анализ

**Промпт 1. Структурирование User Stories**
> «[текст ТЗ]. Сформируй 15–18 User Stories в формате "Я, как [роль], хочу [действие], чтобы [ценность]". Роли: Сотрудник, Руководитель, HR, Админ. Укажи MoSCoW.»

*Результат агента:* Предложил 20 историй, включая технические (например, «Я, как разработчик, хочу, чтобы БД была нормализована»).
*Корректировка:* Технические истории удалены. Оставлены только те, что описывают потребность пользователя. Добавлены истории про 360 и удаление ПДн.

**Промпт 2. Вывод FR из User Stories**
> «На основе этих 16 US выведи FR. Каждое FR должно иметь ID, ссылку на US, Acceptance Criteria (измеримые) и приоритет. Всего 19-21 FR.»

*Результат агента:* Сгенерировал 24 FR. В некоторых AC были формулировки «система должна работать быстро» (неизмеримо). Также агент раздробил US-07 (экспорт) на 3 мелких FR.
*Корректировка:* Неизмеримые AC переписаны (добавлены секунды, проценты). Мелкие FR объединены в один (FR-07). Итог — 21 FR.

**Промпт 3. Проверка NFR и MoSCoW**
> «Проверь мои NFR на измеримость и пересчитай MoSCoW, чтобы доли соответствовали 40-50/25-30/15-20/5-10.»

*Результат агента:* Указал, что NFR-05 (UX) сформулирован как техническое требование (drag&drop), а не как характеристика удобства. Указал на арифметическую ошибку в MoSCoW (было 65% Must).
*Корректировка:* NFR-05 переписан через SUS и время выполнения задач. MoSCoW пересчитан, часть требований перенесена из Must в Should/Could.

**Помог ли агент при выводе FR из US?**
Да, помог. Агент быстро сгенерировал черновик (22 FR), что сэкономило время. Агент выступил как генератор идей и аудитор, но финальные решения принимались вручную.
